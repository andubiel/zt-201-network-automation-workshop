== About this workshop

Module-1 teaches advanced network automation using Red Hat Ansible Automation Platform. 

This immersive, hands-on workshop highlights the power and capabilities of AAP in automating real-world network scenarios. As a continuation of the Introduction to Ansible Network workshop, this session introduces advanced concepts, including Source of Truth (SoT), dynamic inventories, compliance, configuration drift, and state validation. Rather than focusing on extensive playbook development from scratch, participants will explore the "art of the possible" by building production-ready workflows and robust network validations.

== Learning objectives

By the end of this workshop, you will be able to:

* Demonstrate the art of the possible:  Explore real-world network automation capabilities with Ansible Automation Platform
* Establish source of truth: Use Netbox as a dynamic inventory source and Git for network device configurations
* Manage network compliance and drift control: Validate configuration standards and restore devices to known-good states
* Automate multi-vendor EVPN VXLAN:  Apply foundational knowledge and best practices for automating spine-leaf architectures
* Tune Ansible for scale: Configure Ansible to execute changes across large network fabrics efficiently

== Target audience

This workshop is designed for:

* Network engineers looking to automate repetitive tasks
* Systems administrators expanding into network automation
* Automation architects evaluating Ansible for network infrastructure
* Network security engineers looking to automate compliance and remediations
* Anyone interested in hands-on network automation experience

== What you need to succeed with Module-1

You should have:

* Basic networking knowledge (routing, switching, VLANs, VXLAN)
* Familiarity with the Linux command line
* A web browser for accessing the lab environment
* Recommended to complete "Introduction to Ansible Automation Workshop" prior to completing this workshop

## Module 1: Lab Topology Summary

### Network Fabric Devices
- **6 total devices** in spine-leaf EVPN VXLAN topology
- **2 spine switches**: Arista EOS (spine1, spine2)
- **4 leaf switches**: 2x Arista EOS (leaf1, leaf2) + 2x Cisco NX-OS (leaf3, leaf4)
- All devices accessible via LoadBalancer ports 2222-2227

### Supporting Infrastructure
- **ansible-1**: Containerlab VM hosting network topology
- **Netbox**: Source of truth and dynamic inventory
- **AAP Controller**: Automation orchestration platform

### Automation Platform Components
- **4 Organizations**: Network, Compute
- **Multiple Execution Environments**: Network EE, Netbox EE
- **10+ Job Templates**: Covering inventory, backups, compliance, configurations
- **5+ Workflows**: Automated multi-step processes
- **4 Teams with RBAC**: Network-admin, network-operator roles
