== Step 3: Examining the Inventory as Code

The scope of a `play` within a `playbook` is limited to the groups of hosts declared within an Ansible **inventory**. Ansible supports multiple link:http://docs.ansible.com/ansible/latest/intro_inventory.html[inventory^] types. An inventory could be a simple flat file with a collection of hosts defined within it or it could be a dynamic script (potentially querying a CMDB backend) that generates a list of devices to run the playbook against.

In this lab you will work with an automation controller GUI based inventory called "Workshop Inventory". The "Workshop Inventory" was pre-configured during the lab setup using controller_as_code. 

See below snipit of code from the playbook `controller_workshop_objects.yml` Observe how the groups, hosts and related groups were constructed. The following playbook uses modules from the ansible.controller collection:

== Step 5 : Open Netbox

Navigate to the Netbox tab

image::netbox_tab.png[Playbook,align="center",link=self,window=_blank,width=800]

NetBox Overview

  * username: admin
  * password: admin@123
 
 
NetBox is an open-source web application that serves as an Infrastructure Resource Modeling (IRM) tool and source of truth for network infrastructure.
 
It's designed to document and manage:

  * IP address management (IPAM)
  * Data center infrastructure (racks, devices, cables)
  * Network equipment inventory
  * Virtualization resources
  * Circuits and connections

Why Use NetBox as an Ansible Inventory Source?

Dynamic, Always Current Inventory

  * Instead of maintaining static YAML/INI files, Ansible queries NetBox in real-time
  * Inventory automatically reflects infrastructure changes without manual updates
  * Eliminates drift between documentation and automation

 Take a look at the `netbox_inventory.yml` file from VSCode tab.
 The credentials needed to log into Netbox are read in automatically 
 as environment variables from the `Netbox Credential`.

netbox_inventory.yml

[source:yaml]
----
---
plugin: netbox.netbox.nb_inventory
validate_certs: false
config_context: false
group_by:
  #- sites
  - device_types

compose:
  ansible_network_os: custom_fields.ansible_network_os
  ansible_port: custom_fields.ansible_port
  ansible_host: custom_fields.ansible_host
  ansible_connection: custom_fields.ansible_connection
  ansible_become: custom_fields.ansible_become
----

Lastly the ansible.cfg file will use the auto plugin to envoke the `netbox_inventory.yml file.

[source:ini]
----
[inventory]
enable_plugins = host_list, script, yaml, ini, auto
----
